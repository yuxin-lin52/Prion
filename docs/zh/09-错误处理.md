# 09 错误处理

Prion 没有异常。可能失败的操作返回一个**和类型**，调用方用 `match` 解构。本章演示这个模式。

## 用和类型表示错误

```anle
add type "res" = "ok"(int) | "err"(str)
```

函数成功时返回 `"ok"(值)`，失败时返回 `"err"(消息)`：

```anle
add fn "safe_div" (a int, b int) "res" = if b == 0 { "err"("divide by zero") } else { "ok"(a / b) }
```

## 用表达式形态 match 传播

在函数体里，`match` 也是表达式。这让你在转换结果的同时把错误透传下去：

```anle
add fn "double_div" (a int, b int) "res" = match call fn "safe_div"(a, b) { case "ok"("v"): "ok"(call val "v" * 2), case "err"("why"): "err"(call val "why") }
```

## 用语句形态 match 消费

在调用处 match 结果并处理：

```anle
match call fn "double_div"(10, 2):
    case "ok"("v"):
        print("ok", call val "v")
    ;
    case "err"("why"):
        print("err", call val "why")
    ;
;
```

## 动手试试

```anle
#: main b
    add type "res" = "ok"(int) | "err"(str)
    add fn "safe_div" (a int, b int) "res" = if b == 0 { "err"("divide by zero") } else { "ok"(a / b) }
    add fn "double_div" (a int, b int) "res" = match call fn "safe_div"(a, b) { case "ok"("v"): "ok"(call val "v" * 2), case "err"("why"): "err"(call val "why") }

    match call fn "double_div"(10, 2):
        case "ok"("v"):
            print("success", call val "v")
        ;
        case "err"("why"):
            print("failure", call val "why")
        ;
    ;
    match call fn "double_div"(10, 0):
        case "ok"("v"):
            print("success", call val "v")
        ;
        case "err"("why"):
            print("failure", call val "why")
        ;
    ;
#: main d
```

预期输出：

```
success 10
failure divide by zero
```

## 为什么这样设计

- 失败是类型的一部分，所以编译器能检查你处理了它。`match` 的穷尽性意味着：新增一个错误变体，会暴露每一处需要更新的代码。
- 没有隐藏的控制流：没有异常展开，没有套着展开的清理栈。调用方在返回类型里看到错误，并决定怎么处理。
- 标准库的 `result(T, E)` 与 `option(T)` 就是这么打造的；最常用的内置名见附录。
