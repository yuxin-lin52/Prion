# 13 可移植性

## 概述

Prion 经 LLVM 提前编译为原生代码，产物中没有虚拟机，也没有运行时依赖。

## 构建模式

```
prionc build [name] --mode debug|release --opt 0-3
```

- `debug`——全护栏（越界与空检查）；缺省 `--opt 0`。
- `release`——优化并抽掉全部护栏；缺省 `--opt 3`。越界与空访问成为未定义行为，因此应先在 `debug` 下测试。

模式决定产物目录：`build/<模式>/<名>.exe`。

## 命令

| 命令 | 作用 |
|---|---|
| `prionc build [name]` | 编译并链接 |
| `prionc run [name]` | 构建后运行；`--` 之后的参数传给程序 |
| `prionc check [name]` | 只跑前端，不产文件 |
| `prionc fmt [path] [--check]` | 补装饰性缩进 |
| `prionc clean [name]` | 删除 `build/` 目录 |
| `prionc -V` / `prionc -h` | 版本 / 用法 |

## 目标

LLVM 后端支持 `x86` 与 `aarch64`。代码生成使用 LLVM 22，并用 `clang` 链接。

## 环境

- `PRION_CC`——用于链接的 `clang`，也是兜底工具链。
- `PRION_STD`——标准库根；按 SDK 布局放好时不必设置。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 101 | Prion 错误（已打印诊断） |
| 1 | 用法错误 |

`run` 透传程序自身的退出码（0–255）。

## 产物布局

```
build/debug/hello.exe      // 可执行文件
build/debug/hello.ll       // LLVM IR
build/debug/hello.o        // 目标文件
```

## 工具链解析

编译器不会静默替换为不兼容的工具链。若 `PRION_CC` 指向的编译器无法链接，会报告失败；应当修正工具链，而不是绕过它。
