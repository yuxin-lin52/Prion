# 13 可移植性与目标

Prion 经 LLVM 提前编译为原生可执行文件。产物里没有虚拟机，也没有运行时依赖。

## 构建模式

```
prionc build [name] --mode debug|release --opt 0-3
```

- `debug`——全护栏（越界检查、空检查）。缺省 `--opt 0`。
- `release`——优化，护栏全部抽掉。缺省 `--opt 3`。越界与空引用会变成未定义行为，所以先在 `debug` 下测。

模式决定产物目录：`build/<模式>/<名>.exe`。

## 运行

```
prionc run hello
```

`run` 先构建再执行。`--` 之后的参数原样传给程序。

## 只检查

```
prionc check hello
```

`check` 跑前端（词法 → 语法 → 检查），不产任何文件。是验证代码最快的方式。

## 目标

LLVM 后端支持 `x86` 与 `aarch64`。代码生成用 LLVM 22 工具链，并用 `clang` 链接。

## 环境

- `PRION_CC`——用于链接的 `clang`（也作为兜底工具链）。
- `PRION_STD`——标准库根；若按 SDK 布局放好则不必设。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 101 | Prion 错误（已打印诊断） |
| 1 | 用法错误 |

`run` 透传程序自己的退出码（0–255）。

## 产物布局

```
build/debug/hello.exe      // 可执行文件
build/debug/hello.ll       // LLVM IR（调试用）
build/debug/hello.o        // 目标文件
```

`prionc clean` 删除整个 `build/` 目录。

## 不对环境做静默兜底

编译器不会自动探测一个「兼容」的工具链并悄悄降级。若 `PRION_CC` 指向的编译器链接不了，你会得到明确错误——去修工具链，而不是绕过它。
