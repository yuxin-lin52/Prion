## 方法

- 取整个进程的墙钟时间，**10 次运行取中位数**；最小值与最大值在 JSON 结果里。
- JVM、.NET、Go、Swift 先跑一次空的 `none` 项测启动基线，再相减。
- 每个基准要求所有语言输出一致，才纳入统计。
- `num` 与 `index` 用 `s = (s * 31 + x) % 1000000007` 递推，使编译器无法把求和折成闭合公式、也无法把内层循环整体外提。
- `concat` 每轮都用三段拼接出一个新的 6 字节字符串。

| Go | 0.30 s | 1624 KB |
| Prion | 2.03 s | 1200 KB |

编译耗时是删除产物后、工具链缓存已热的一次完整构建。C++、Rust、Java、C#、Go、Swift
是「单个源码含全部模式」，Prion 与 Zig 是六个程序分别构建——这两列是六次构建的合计。

## 数字怎么看

- **数组与哈希表**：数组遍历与 C++/Rust/Zig 同一水平；哈希表与 Rust/Zig 同一水平。
- **标量计算与递归**：中游——`num` 比 C++/Rust 慢约 8%，`fib` 比 C++ 慢约 25%、比 Java 慢约 53%。
- **字符串构造**：最弱项。Prion 每次 `concat` 分配一次，与 Rust 同一模型（53.0 ms）；
  C++ 与 Zig 分别靠短串内联（SSO）和更快的分配器省掉了逐次分配。
  Prion 按设计不做短串内联，也不加分配池。
- **内存**：峰值与原生语言同一量级，远低于 JVM。
